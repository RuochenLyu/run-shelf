## Considered and rejected for this repair program

- Swift 6 migration: no current EOL or removal pressure was found; it adds churn
  before the reliability baseline is secure.
- Full sandboxing: the product deliberately executes user-owned shell scripts;
  changing that boundary needs a separate product design, not a bug-fix plan.
- Database-backed history: the file-native SSOT already supports bounded and
  directed reads; a database would add migration and consistency costs.
- Treating the dangerous-command scanner as a security sandbox: documentation
  defines it as a warning heuristic, so strengthening it is future product work.
- Implementing non-local timezones while fixing validation: current runtime uses
  local time only; the repair is to reject unsupported values, not silently add a
  scheduling feature.
